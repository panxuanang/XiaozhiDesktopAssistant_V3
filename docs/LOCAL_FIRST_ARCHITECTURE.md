# Local-first 执行架构

## 原则

```text
本地文件/系统 API
> pandas/openpyxl/python-docx/python-pptx
> DOM/UI Automation
> 快捷键
> 本地 OCR
> AI API（语义层）
> 坐标点击（最后兜底）
```

AI 不是执行器。它只在确定性代码无法完成“理解/写作/规划”时参与。

## Excel 模糊任务的最小 API 用法

例如老板说：

> 按地区把这个表重新弄一下，不达标的标出来。

客户端先本地读取列名和少量样例。如果规则可以匹配“地区/目标/实际”，直接本地规划；否则才把列名 + 用户要求发给 API，请模型返回：

```json
{
  "operations": [
    {"op":"group_sum","group_by":"区域","values":["销售额"],"sheet":"区域汇总"},
    {"op":"mark_below_target","value":"销售额","target":"目标","status":"达成状态"}
  ]
}
```

模型不能返回/执行任意 Python，只能选择白名单操作。真正修改工作簿仍由本机代码完成。

## 为什么不默认让小智后台写

V0.2.0 的目标是让用户可以控制成本和数据路径。小智后台负责语音和 MCP 路由，电脑端尽量在本地执行；需要语义能力时才调用用户自己选择的 API。


## V0.3 联网调研的数据路径

```text
搜索引擎
→ 本地 Chrome/Edge
→ 搜索结果 URL
→ 本地逐页提取 DOM 正文
→ 本地提取式摘要
→ （可选）仅把多来源短摘要一次性交给用户 API 综合
→ 本地 python-docx 生成报告
→ 微信本地 UIA/快捷键发送（仍需确认）
```

不会为了“找网页”和“读网页”调用生成式 AI。真正需要 API 的只是最终跨来源综合写作，而且 API 不可用时仍能生成纯本地来源汇编报告。

## V0.3 Excel 批处理原则

同一个文件夹里的几十个 Excel 不应每个文件调用一次模型。客户端先根据第一个工作簿的列名生成一次受限计划，然后把该计划复用到后续工作簿。支持的计划仍是白名单操作，禁止模型注入任意 Python。
