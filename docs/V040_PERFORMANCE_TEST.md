# V0.4.0 Windows 真机性能验收清单

建议全部录下“说完指令到电脑开始动作”的时间，并用 `performance_report` 对照。

## A. 快车道：必须 0 次用户 API

依次说：

1. `打开记事本`
2. `打开百度`
3. `打开浏览器`
4. `百度搜一下人工智能`
5. `最大化记事本`
6. `音量调到 30%`
7. `截图`
8. `把桌面的测试文件.xlsx发给文件传输助手`

预期：前 7 项直接动作；第 8 项只准备并询问确认。`performance_report` 不应显示这些任务有 API 调用。

## B. 微信确认与发送

1. 微信已经登录。
2. 先只测试“文件传输助手”。
3. `把桌面的测试文件.xlsx发给文件传输助手`
4. 小智应询问确认。
5. `确认发送`
6. 检查焦点是否进入聊天输入区。
7. 检查文件是否真的出现在聊天记录。
8. 再测试文字配文。
9. 最后再测试真实联系人。

失败时记录微信版本、窗口是否最大化、是否弹出升级/登录窗口，并查看日志。不得因为未验证到 UIA 文本就谎报“确认成功”。

## C. 内容读取：不要误触发写作 API

- `总结一下这个网页`
- `分析一下这个 Excel`
- `快速总结这个 PDF`

网页本地提取式总结和明确 Excel 本地分析应尽量本地；只有用户要求正式综合写作/语义改写时才用 API。

## D. 写材料：应比 V0.3 少一次 API

说：

`写一份 1200 字工作总结并生成 Word 放桌面`

预期：内容生成使用 1 次 API，请求同时给出标题和正文，本地生成 DOCX；不应再单独调用第二次 API 起标题。

## E. 复杂任务：允许 API，但不能“无限等”

- 多来源网页调研 -> Word 报告
- 模糊 Excel 整理要求 -> 受限计划 -> 本地执行
- 真正需要通用 Agent 的跨应用任务

预期：Agent 只看到相关领域工具，默认最多 4 轮；单次 Agent API 超时 25 秒。断网/401/429 不应再切另一 API 协议等待第二遍。

## F. MCP 工具面

普通模式应主要看到：

- workmate
- task_center
- search_work_files
- performance_report

如果仍看到几十个低层工具：

1. 确认 `expose_low_level_tools=false`。
2. 完全退出旧托盘客户端。
3. 重新启动 V0.4。
4. 让 MCP 断开并重新连接，刷新服务端工具缓存。

## G. 重点回归

- 不得再出现 V0.3.1 那种“只回答、不执行”。
- 打开网页后不得自动念网页正文。
- 微信/定时发送确认不能被性能优化绕过。
- 文件删除、系统命令、关闭可能未保存窗口仍需安全确认。
- 浏览器冷启动后，第二句 DOM/总结指令仍能接入同一个专用 DevTools 配置。
- 旧配置/API Key/任务数据库升级后仍在。
- 安装时不要同时运行多个旧/新托盘进程。
