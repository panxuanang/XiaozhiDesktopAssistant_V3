# 小智打工人搭子 V0.4.0 性能版升级说明

这是针对你当前 `XiaozhiDesktopAssistant_V3` V0.3.x 仓库的 **覆盖升级包**。核心不是删功能，而是把执行链重新分成“本地快车道”和“复杂 AI 慢车道”。

## 上传 GitHub

1. 解压 ZIP。
2. 进入解压后的 `xiaozhi_v040_upload_ready` 目录。
3. 把**里面的内容**拖到 GitHub 仓库根目录。
4. 同路径文件覆盖后提交。
5. 不要把 `xiaozhi_v040_upload_ready` 本身套在仓库里。
6. 运行 `Actions -> Build Windows EXE`。

本包是增量覆盖包：没有出现的原 V0.3 文件继续保留，不要删除仓库其它文件。

## Windows 覆盖安装

建议：

1. 先退出旧版右下角托盘程序。
2. 运行 `XiaozhiDesktopAssistant-Setup-0.4.0.exe`。
3. 安装器会尝试关闭仍在运行的同名旧 EXE。
4. 不要删除 `%APPDATA%\XiaozhiDesktopAssistant`，这里有 API Key、MCP 地址、任务数据库、日志和浏览器配置。
5. 安装后重新启动客户端，让小智 MCP 重新连接并刷新工具列表。

如果小智后台曾缓存旧的几十个工具，至少完整退出一次电脑客户端再重新启动；必要时在小智后台断开/重新连接一次 MCP。

## 这版最重要的行为变化

普通模式小智只需要看到 4 个工具，电脑任务统一交给 `workmate`。电脑端内部执行顺序：

```text
用户说话
  -> 小智后台识别/路由
  -> workmate
  -> 本地零API快车道（能确定就直接做）
  -> 原有本地 workmate 规则
  -> 只有最后才用 desktop_agent / 用户自己的API
```

### 应该 0 次用户 API 的例子

- “打开记事本”
- “打开百度”
- “打开浏览器”
- “百度搜一下人工智能”
- “音量调到 30%”
- “截图”
- “把桌面的测试文件.xlsx发给文件传输助手”（只准备并要求确认）
- “确认发送”（本地微信自动化）
- 明确的 Excel 求和、筛选、拆表、去重、批处理等本地规则任务

### 允许使用 API 的例子

- “写一份 1200 字正式工作总结，生成 Word”
- “把几个网页综合成正式调研报告”
- Excel 指令过于模糊，本地规则无法安全映射时，只让模型生成受限计划
- 最后的通用语义 Agent 兜底

## 写材料也减一次 API

V0.3 默认正文一次 API + 起标题一次 API。V0.4 一次请求同时得到标题和正文，然后本地生成 Word。

## API 超时策略

- 旧默认 120 秒自动迁移到 45 秒。
- 通用 Agent 默认 25 秒。
- SDK 自动重试 0。
- `auto` 模式不会在网络超时、401、429 等错误之后又换协议再等一遍。

## 浏览器策略

“打开/搜索”只负责快速发出动作，不读取、不总结。

真正说“总结这个网页”“点击网页上的登录”“提取这个网页表格”时，才进入 DevTools/DOM 路径。因此冷启动 Chrome/Edge 后，第一句可以很快返回，页面在后台继续加载；第二句内容操作再等待页面结构就绪。

## 微信策略

文件发送仍然是：

```text
UIA 找/激活微信
-> Ctrl+F 搜联系人
-> UIA 优先聚焦聊天输入区
-> Windows CF_HDROP 把文件放入剪贴板
-> Ctrl+V
-> Enter
-> UIA 短时验证
```

UIA 找不到输入区时才使用**微信窗口相对位置**点击兜底，不使用固定屏幕坐标。发送继续要求明确确认。

## 查看究竟慢在哪里

V0.4 增加 `performance_report`。最近记录会显示类似：

```text
xiaozhi_workmate: 420ms | route=browser_open, tools=1
xiaozhi_workmate: 16800ms | route=local_workmate, API=1, tools=1
```

这样可以区分是电脑本地、浏览器、微信还是用户自己的 API 慢。

## 回滚

如果某台 Windows 真机出现兼容性问题，可以重新安装原 0.3.x 安装包。AppData 数据默认不删除。
